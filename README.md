## 👋 About Me

I'm **Yahya AFFAN**. My interests sit at the intersection of software engineering and security — especially the mechanisms that protect applications, identities, and digital infrastructure.

I like understanding what happens behind the interface: how an application authenticates a user, how permissions are enforced, how sensitive information is protected, and how activity can be audited afterwards.

My hands-on work focuses on:

- 🔐 **Authentication** — secure user sessions and JWT-based authentication.
- 🛡️ **Access control** — role-based permissions and IAM concepts.
- ⚙️ **Application security** — password hashing, rate limiting, secure HTTP headers, and API security.
- 🧾 **Auditability** — activity logs and traceable security events.
- ☁️ **Cloud security** — developing my knowledge of AWS IAM, KMS, detection engineering, and cloud security posture.

My direction is **cloud security engineering**: combining software development fundamentals with the ability to design, understand, and strengthen secure systems.

> **The question behind my work:** Who is allowed to do what — and how can we prove it?

## 🏗️ Behind the Portfolio

I designed and built this website as a personal professional portfolio — not as a software product or framework. The goal was to create a distinctive place to present my profile, projects, experience, and education in a way that feels cohesive and easy to explore.

### Technology & architecture

| Layer | Implementation |
|---|---|
| **Structure** | Semantic HTML5 |
| **Visual system** | CSS3, custom layouts, responsive styling |
| **Application logic** | Vanilla JavaScript |
| **Content model** | Centralized content and translation object |
| **Navigation** | Lightweight hash-based routing |
| **Language preference** | Browser local storage |
| **Typography** | Google Fonts |
| **Hosting** | GitHub Pages |

### 🌍 One portfolio, three languages

The site supports **English, French, and Chinese**. Rather than maintaining three separate websites, I organized translated content in a centralized JavaScript object (`T`). The interface reads from the selected language, keeping the structure and navigation consistent.

### 🧩 How the interface works

- **Hash-based navigation:** routes such as `#/about`, `#/work/1`, and `#/edu/2` control which section or detail page is displayed.
- **Dynamic rendering:** JavaScript renders the relevant content and navigation from the selected route.
- **Language persistence:** the selected language is saved in local storage and restored on a later visit.
- **Project and education details:** each entry has its own focused detail view.
- **Contact interaction:** the form validates required fields. With no Formspree endpoint configured, it prepares an email through the visitor's default email application.
- **Responsive and accessible structure:** the layout adapts to screen sizes and includes semantic structure and a skip-to-content link.

### 🎨 Design direction

I chose a restrained editorial aesthetic: strong typography, generous spacing, a muted palette, and minimal interface elements. The intention is to keep the focus on the person, the work, and the details — rather than filling the page with generic developer-dashboard visuals.
